# 名医入企 · 北京大学国际医院企业健康合作平台

面向保险公司与企业客户的企业健康服务 H5 演示站，适配微信内置浏览器与手机端访问。
页面采用北京大学国际医院深蓝品牌色与 iOS 风格移动端界面，桌面访问时以 480px 手机预览框居中显示。

## 在线演示

https://baoweidong.github.io/pkuih-enterprise-health/

## 演示能力

- 机构账号无需预分配：任意手机号 + 验证码 `888888` 即可登录；首次登录填写姓名、单位与联系方式，联系手机号默认取登录号码且可修改
- 登录页提供企业演示账号「一键进入」，固定手机号 `13800000001`、验证码 `888888`，无需先注册
- 直接通过微信内置浏览器打开 H5，不依赖公众号授权；使用手机号验证码登录并持久化登录状态
- 自动恢复上次身份：上次为院方账号会直接进入院方工作台，上次为企业账号会保持企业登录态
- 三级专家资源：大咖医生 / 主任专家 / 专业医生
- 59 位专家以“照片/默认头像 + 科室职称 + 擅长简介 + 可服务类型”的信息卡展示，点击可查看完整专家详情
- 专家与履约医院绑定；机构登录后优先展示就近医院可预约专家，并可随时切换到全部地区
- 进入首页自动请求定位并计算到各履约医院的距离；定位不可用时按登录省市回退，可在首页手动切换医院
- 时令主题：进入专家详情后展示当前月份匹配的讲座主题，也可切换查看全年 12 个月主题
- 默认医疗头像：未配置官网照片的专家按性别与资历使用四类医疗头像，不出现空白或纯图片卡片
- 找不到合适专家时，机构可提交活动提需；医院运营可记录电话沟通、匹配专家并关闭需求
- 专家库筛选栏在向下浏览时固定在顶栏下方，切换层级或搜索无需回到页面顶部
- 移动端图片分层加载：首图和列表使用轻量缩略图，专家详情图仅在打开详情时加载
- 服务类型：讲座、巡诊、1 对 1 健康咨询；预约可不指定专家，由医院运营匹配安排
- 三级预约流程：按申请周期选择有号源的日期（只到天，不划分时段），也可指定有档期的专家
- 全国省市联动：覆盖 34 个省级行政区与 380 个城市级选项，预约时按省份加载对应城市，活动详细地址必填
- 预约号源：超级管理员与医院运营可按专家个人配置每日可预约数量；号源页提供专家横向快速切换、单日调整、首约日起 7/14/30 天快捷批量设置和当前专家/本院全部专家批量应用；早于专家预约周期的日期会自动跳过，修改先进入草稿并统一保存，号源不得低于当日已预约数量
- 「我的预约」按登录账号隔离，可查看状态及院方回复的课题、大纲、流程、时间与项目组联系人
- 预约履约流程：机构提交预约 → 医院运营接单并填写活动方案 → 机构确认或提出修改 → 医院运营执行并归档
- 院方工作台：仅限已分配且启用的院方账号登录，支持接单、回复活动方案、确认方案、安排项目组以及活动结束后归档
- 院方角色：仅保留超级管理员与医院运营。超级管理员拥有全部医院权限，医院运营负责本院专家、号源、接单与项目跟进
- 医院账号：超级管理员可在「医院与账号」中创建、编辑、停用医院运营账号，并为每家医院分配运营人员；医院运营只能维护本院数据
- 专家配置：超级管理员与医院运营可新增或编辑本院专家，维护姓名、层级、医院、科室职称、服务类型、擅长方向、简介、申请周期、时令主题并上传照片
- 展业物料：超级管理员与医院运营均可进入「展业物料」，按客户场景选择权威主视觉、专家阵容、企业健康价值或保险高客答谢海报
- 宣传海报：4 套海报均由院方统一设计，突出医院权威、名医资源与服务价值；海报不展示项目人员姓名和联系方式，仅保留预约二维码
- 海报加载：预置 4 套 1080×1920 轻量 WebP 海报与缩略图，列表只加载缩略图，打开预览时才加载完整海报，无需现场生成
- 院方人员自动带入：处理预约时，当前登录人员的姓名与手机号会自动填入项目组联系人和客户短信
- 活动备注：企业可填写活动需求备注，院方内部备注采用查看/编辑两种状态展示，仅院方可见
- 短信跟进：不再统一配置模板。院方填写课题确认信息后自动生成客户短信；复制短信内容或“号码和内容”后，自动视为已发送并记录人员与时间
- 短信待办：已确认但尚未复制客户短信的项目会自动进入「短信跟进」待提醒列表
- 院方入口：已从「我的」移动到首页最下方
- 全部演示数据保存在浏览器 `localStorage`，无需后端即可演示预约闭环
- 首次打开自动写入 3 条企业预约样例（待接单、方案待确认、已确认）和 2 条提需样例，登录演示账号即可直接体验完整流程
- 页面不展示价格、报价或费用信息
- 支持安卓微信边缘滑动返回：弹层、登录页、院方工作台与二级地点编辑均按层级返回，不会直接退出业务页面
- 登录、筛选、切换层级、选择日期与专家均使用局部刷新，不重建整页，并保留当前浏览位置

## 说明

本项目为静态交互 Demo：

- 验证码固定为 `888888`，不会实际发送短信
- 页面不依赖微信公众号授权，直接分享 H5 链接即可在微信内置浏览器访问
- 客户短信仅生成并复制内容，不调用短信网关；复制短信内容或“号码和内容”后才视为已发送
- 短信跟进记录保存在浏览器本地，正式版本需接入真实短信发送状态与审计系统
- 手动短信功能只负责生成和复制号码及内容，仍需院方在手机短信应用中自行发送
- 院方演示账号和密码保存在浏览器本地，未接入真实身份认证与权限审计；正式上线必须改为后端鉴权
- 专家上传照片会压缩后保存在浏览器本地，正式版本需接入对象存储、图片审核与内容管理后台
- 展业海报为预置静态图片，打开即可预览和保存，不在浏览器现场合成；海报不含项目人员姓名和手机号，二维码统一指向企业健康服务平台；正式版本建议接入渠道参数、分享追踪与素材审核
- 号源配置与预约记录目前共用一个浏览器本地数据源，正式版本需接入后端库存、并发锁与订单系统
- 账号鉴权、真实预约库存、消息通知与文件上传需在正式版本中接入医院业务后端

专家照片与简介来自北京大学国际医院官网公开资料，仅用于本项目演示。实际出讲专家、活动排期与授权以院方最终确认为准。

医院地址与经纬度按公开地图信息整理；深圳北医康复医院当前使用南山区近似坐标，正式上线前需由院方核实门牌地址与定位点。

本地预览：

```bash
python3 -m http.server 8080
```

## 技术说明

- 当前演示仍为原生 JavaScript 单页实现，业务状态集中在 `assets/app.js`，样式在 `assets/styles.css`
- 技术团队已确定正式版本采用 Vue 3。当前阶段优先稳定业务闭环与移动端交互，Vue 3 组件化迁移作为下一阶段单独实施
- `index.html` 加载压缩后的 `assets/app.min.js` 与 `assets/styles.min.css`；源码修改后执行：

```bash
npx esbuild assets/app.js --minify --legal-comments=none --outfile=assets/app.min.js
npx esbuild assets/styles.css --minify --legal-comments=none --outfile=assets/styles.min.css
```

- 专家、医院、时令主题与主题匹配数据位于 `assets/data/*.json`，全国省市数据位于 `assets/china-cities.json`
- 官网专家图片按卡片图与详情图分别存放于 `assets/doctors/cards/`、`assets/doctors/details/`，默认头像位于 `assets/avatars/`
- 展业海报位于 `assets/posters/`（WebP），缩略图位于 `assets/posters/thumbs/`，海报设计源文件位于 `work/poster-tools/build-promo-posters.cjs`
- 正式版本建议由后端提供登录鉴权、号源库存与并发控制、预约状态机、短信发送记录与图片对象存储
