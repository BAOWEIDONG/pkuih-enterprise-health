# 名医入企 · 北京大学国际医院企业健康合作平台

面向保险公司与企业客户的企业健康服务 H5 演示站，适配微信内置浏览器与手机端访问。
页面采用北京大学国际医院深蓝品牌色与 iOS 风格移动端界面，桌面访问时以 480px 手机预览框居中显示。

## 演示能力

- 机构账号采用手机号白名单：超级管理员开通时只需填写手机号与姓名，其余资料选填；机构人员首次登录必须补全单位、机构类型、职务、联系方式和通知邮箱后才能进入（机构类型含保险公司、银行、证券、基金、信托、企业、事业单位与其他机构）
- 登录页提供企业演示账号「一键进入」，固定手机号 `13800000001`、验证码 `888888`，无需先注册
- 企业资料中的所在省市不再手工填写，自动跟随定位或首页切换的城市，并在城市变化时同步更新
- 通知邮箱为必填项，用于生成方案更新与预约确认邮件；联系方式默认取登录手机号，可修改
- 直接通过微信内置浏览器打开 H5，不依赖公众号授权；使用手机号验证码登录并持久化登录状态
- 自动恢复上次身份：上次为院方账号会直接进入院方工作台，上次为企业账号会保持企业登录态
- 三级专家资源：大咖医生 / 主任专家 / 专业医生
- 59 位专家以“照片/默认头像 + 科室职称 + 擅长简介 + 可服务类型”的信息卡展示，点击可查看完整专家详情
- 专家与履约医院绑定；机构登录后优先展示就近医院可预约专家，并可随时切换到全部地区
- 进入首页自动请求定位并计算到各履约医院的距离；定位不可用时按登录省市回退，可在首页手动切换医院
- 首页切换履约医院时同步该院所在城市与本地专家范围，避免异地医院出现“0 位可约”的假象；医院下拉按实际定位距离排序
- 时令主题：首页展示当前医院当月的独立主题封面，点击进入主题介绍页查看本月疾病重点、适合行业、推荐课题、绑定专家与覆盖城市，并可直接预约
- 月度主题配置：每家医院独立维护 12 个月时令名称、介绍、关注疾病、行业与讲座课题；每个课题独立选择一次主讲专家，并单独配置该课题的履约城市（省市级联、可多选、可一键套用专家履约地），不再维护月级“讲座覆盖城市”
- 时令主题城市可见性：机构端首页、主题详情与预约页只展示覆盖当前城市的课题；当前城市不在课题履约地内时不展示，已选课题切换城市后会明确提示“当前城市不可预约”而不是静默消失
- 默认医疗头像：表格未提供性别时统一使用中性医疗头像；院方也可按需选择男/女及资深头像
- 找不到合适专家时，机构可提交活动提需；医院运营可记录电话沟通、匹配专家并关闭需求。提需默认提交至「集团企康办」，这类需求只进入超级管理员需求池，不派发给具体医院运营
- 专家库筛选栏在向下浏览时固定在顶栏下方，切换层级或搜索无需回到页面顶部
- 专家库默认展示当前地区、当前医院的可预约专家，默认不启用月份时令筛选；启用月令后仅展示讲座，并可一键清除月令筛选
- 移动端图片分层加载：首图和列表使用轻量缩略图，专家详情图仅在打开详情时加载
- 服务类型：`讲座`、`健康咨询`、`1V1报告解读` 严格按院方专家配置匹配；当前医院没有对应专家时，预约页直接引导发起提需
- 三级预约流程：专家为必选项，按专家申请周期选择有号源的日期（只到天，不划分时段）；已选专家再次点击可取消
- 预约页将“查看简介”与“选择专家”拆分为独立操作；时令主题为可选项，点击选择、再次点击取消
- 全国省市联动：覆盖 34 个省级行政区与 380 个城市级选项，预约时按省份加载对应城市，活动详细地址必填
- 预约号源：超级管理员与医院运营可按专家个人配置每日可预约数量；号源页统一为“选专家 → 批量设置 → 单日微调 → 统一保存”，支持未来 7/14/30 天快捷范围与当前专家/本院全部专家批量应用；早于专家预约周期的日期自动跳过，号源不得低于当日已预约数量
- 「我的预约」按登录账号隔离，可查看状态及院方回复的课题、大纲、流程、时间与项目组联系人
- 预约履约流程：机构提交预约 → 医院运营接单并填写活动方案 → 机构确认或提出修改 → 医院运营执行并归档
- 院方工作台：仅限已分配且启用的院方账号登录，支持接单、回复活动方案、确认方案、安排项目组以及活动结束后归档
- 院方角色：仅保留超级管理员与医院运营。超级管理员拥有全部医院权限，医院运营负责本院专家、号源、接单与项目跟进
- 医院账号：超级管理员可在「医院与账号」中创建、编辑、停用医院运营账号，并为每家医院分配运营人员；医院运营只能维护本院数据
- 专家配置：超级管理员与医院运营可新增或编辑本院专家，按院方表格维护姓名、履约机构、科室/任职、科室方向、服务类型、履约城市、擅长/专业优势、简介/履历、预约提前期并上传照片；已绑定时令课题的主讲专家会校验讲座服务能力与履约机构，避免配置冲突
- 专家筛选：专家库可按月份时令与科室方向筛选，切换时只局部刷新结果并保留当前浏览位置
- 履约城市：专家覆盖城市与课题履约地均使用省份/城市联动选择；专家覆盖城市决定普通讲座、健康咨询与 1V1 的日常履约范围，课题履约地决定时令主题在哪些城市可见可约。含“京外”或“省外”的履约地统一按全国可履约处理
- 筛选一致性：服务类型、可约状态、梯队、科室、搜索与月份时令共用同一筛选结果集，筛选计数、空状态和专家卡片保持一致
- 时令履约地独立：普通讲座、健康咨询、1V1 报告解读按专家日常履约城市判断；时令主题与预约按具体课题的履约地判断，两套范围互不混用。课题履约地可跟随专家，也可按课题单独配置
- 展业海报：超级管理员统一配置官方海报；医院运营可下载、分享官方海报，也可上传本院自有海报并分享给客户
- 宣传海报：预置 4 套院方标准海报，突出医院权威、名医资源与服务价值；海报不展示项目人员姓名和联系方式，仅保留预约二维码
- 海报加载：预置 4 套 1080×1920 轻量 WebP 海报与缩略图，列表只加载缩略图，打开预览时才加载完整海报；上传海报会自动压缩，避免现场生成拖慢操作
- 院方人员自动带入：处理预约时，当前登录人员的姓名与手机号会自动填入项目组联系人和推送通知
- 活动地点分工：省份、详细地址与场地名称由机构预约/详情中填写，机构可单独修改；院方方案只读展示并自动同步，不覆盖机构填写内容
- 方案附件：院方可上传 PDF、PPT 或 PPTX，单个文件不超过 20MB；PDF 支持应用内预览，也可点击「微信内打开」交给微信浏览器查看；PPT/PPTX 微信不支持直接渲染，提供下载后用 WPS/PowerPoint 打开，机构端仅可查看自己预约的附件
- 活动备注：企业可填写活动需求备注，院方内部备注采用查看/编辑两种状态展示，仅院方可见
- 推送通知：院方填写课题确认信息后，按该机构与提需人的当前资料自动组合生成个性化短信和邮件文案；院方复制后记录人员与时间
- 推送入口：院方工作台不再单设「短信」标签，统一在预约详情的「推送通知」卡片内查看并复制；标签栏更精简
- 院方入口：已从「我的」移动到首页最下方
- 业务演示数据保存在浏览器 `localStorage`，方案附件二进制保存在 `IndexedDB`，无需后端即可演示预约闭环
- 首次打开自动写入 4 条企业预约样例（待接单、方案制作中、方案待确认、已确认）和 2 条提需样例，登录演示账号即可直接体验完整流程
- 页面不展示价格、报价或费用信息
- 支持安卓微信边缘滑动返回：弹层、登录页、院方工作台与二级地点编辑均按层级返回，不会直接退出业务页面
- 浏览器滚动恢复由应用统一管理：关闭弹层、切换筛选或返回列表时保留原浏览位置，不会被浏览器历史恢复覆盖
- 登录、筛选、切换层级、选择日期与专家均使用局部刷新，不重建整页，并保留当前浏览位置

## 说明

本项目为静态交互 Demo：

- 验证码固定为 `888888`，不会实际发送
- 页面不依赖微信公众号授权，直接分享 H5 链接即可在微信内置浏览器访问
- 推送通知仅生成并复制内容，不调用短信网关或邮件服务，不需要供应商、模板审核、发送回执或失败重试
- 复制记录保存在浏览器本地，正式版本可持久化复制记录与操作人，不要求记录真实发送结果
- 推送功能只负责生成和复制号码及内容，仍需院方在手机短信或邮件应用中自行粘贴发送
- 院方演示账号和密码保存在浏览器本地，未接入真实身份认证与权限审计；正式上线必须改为后端鉴权
- 专家上传照片会压缩后保存在浏览器本地，正式版本需接入对象存储、图片审核与内容管理后台
- 方案附件当前保存在浏览器 `IndexedDB`，仅用于 Demo；正式版本需接入对象存储、文件鉴权、病毒扫描与附件审核，并限制可访问的预约与账号范围
- 展业海报由超级管理员维护官方素材，医院运营可上传本院自有素材并保存、下载或分享；海报不含项目人员姓名和手机号，二维码统一指向企业健康服务平台；正式版本建议接入渠道参数、分享追踪与素材审核
- 号源配置与预约记录目前共用一个浏览器本地数据源，正式版本需接入后端库存、并发锁与订单系统
- 账号鉴权、真实预约库存、消息通知与文件上传需在正式版本中接入医院业务后端；附件下载链接应使用短时签名地址，不能直接暴露存储路径

专家照片与简介来自北京大学国际医院官网公开资料，仅用于本项目演示。实际出讲专家、活动排期与授权以院方最终确认为准。

医院地址与经纬度按公开地图信息整理；深圳北医康复医院当前使用南山区近似坐标，正式上线前需由院方核实门牌地址与定位点。

## 技术说明

- 生产入口已切换为 Vue 3 + Vant 工程（`web/`），Vue 负责运行时、构建与后续组件迁移；现有业务视图通过 `LegacyHost` 挂载，CSS、DOM、交互和滚动行为保持不变
- `web/src/components/LegacyHost.vue` 是唯一兼容层：它只创建原有 `#app`、`#overlay-root`、`#toast` 容器，不覆盖任何业务样式；`index.legacy.html` 保留原始入口用于像素级回归
- `web/tests/visual-parity.mjs` 在 `320 / 390 / 430px` 三种宽度下逐页对比首页、专家、预约、我的，要求 PNG 像素完全一致
- 页面渲染与业务状态位于 `assets/app.js`，样式位于 `assets/styles.css`；Vue 构建继续复用同一套 CSS，不引入会覆盖现有样式的全局 reset
- `assets/config.js` 是唯一运行时配置入口，维护 API 模式、服务地址、请求超时与客户端版本
- `assets/api.js` 是统一基础设施层，负责基础数据加载、HTTP 客户端、请求追踪、CSRF、会话与持久化适配；Cookie 模式自动请求 `/auth/csrf` 并发送 `X-XSRF-TOKEN`
- `docs/API-CONTRACT-V1.md` 定义前后端接口、字段、状态机、权限、幂等与并发规则；正式接入后端时以该契约为准
- `docs/CODE-REVIEW-V1.md` 记录 V1 代码审查结论、已修复风险和生产上线前必须由后端承接的安全事项
- 原始入口 `index.legacy.html` 按 `config → api → app` 顺序加载；正式入口 `index.html` 由 Vue 构建生成
- 修改现有视图后执行：

```bash
npm run build
npm test
```

- 修改 Vue 外壳或迁移页面后执行：

```bash
cd web
npm ci
npm test
cd ..
npm run build:web
```

`npm run build:web` 会重新构建 Vue 产物并同步 `index.html` 与 `static/`，不会改动 `assets/` 中的图片和业务资源。

- `npm test` 会检查 JavaScript 语法、架构边界、API 契约是否完整，并验证压缩产物可以由源码稳定重建

## 后端与开箱运行

后端位于 `server/`，要求 Java 21：

```bash
cd server
mvn spring-boot:run
```

PostgreSQL + 后端容器：

```bash
docker compose up --build
```

健康检查地址为 `http://localhost:8080/actuator/health`。Compose 中的数据库密码只用于本地开发，正式环境请用密钥管理系统覆盖 `.env.example` 中的变量。

- 默认端口 `8080`，H2 文件数据库位于 `server/data/`，首次启动自动写入 9 家医院、59 位专家、12 个月时令主题、144 条课题匹配、机构账号与未来 61 天号源
- `/actuator/health` 提供 Kubernetes/Docker 健康检查；`server/Dockerfile` 和根目录 `docker-compose.yml` 提供 PostgreSQL 本地部署骨架
- 演示机构账号：`13800000001` / 验证码 `888888`
- 超级管理员：`admin / pkuih2026`
- 国际医院运营：`pkuih / pkuih2026`
- 生产 PostgreSQL 通过 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`DB_DRIVER=org.postgresql.Driver` 配置
- 跨域联调通过 `CORS_ALLOWED_ORIGINS` 配置；正式环境建议同域反向代理 `/api`，并设置 `SESSION_COOKIE_SECURE=true`
- `server/src/main/resources/db/migration/` 已接入 Flyway；主配置使用 `ddl-auto: validate`，现有 H2/PostgreSQL 数据库首次启动会自动建立迁移基线
- `server/src/test/java/com/pkuih/enterprisehealth/CoreFlowIntegrationTest.java` 覆盖机构登录、号源查询、下单、院方接单、提交方案、机构确认、提需分流、提需预留、停用账号会话、幂等冲突与号源版本冲突
- `server/src/test/java/com/pkuih/enterprisehealth/SchemaMigrationIntegrationTest.java` 使用 H2 执行全部 Flyway 迁移，再校验 JPA 实体与表结构一致

Vue 本地开发默认代理 `/api` 到 `http://localhost:8080`；联调后端时在 `web/.env.local` 中设置：

```bash
VITE_API_MODE=api
VITE_API_BASE_URL=/api/v1
VITE_AUTH_MODE=cookie
VITE_DEV_API_TARGET=http://localhost:8080
```

当前静态演示页仍使用浏览器本地业务数据；正式页面接入时复用 `assets/api.js` 与 `docs/API-CONTRACT-V1.md`，不要在组件内直接拼接请求。`PkuihApi.experts`、`PkuihApi.slots`、`PkuihApi.appointments`、`PkuihApi.demands` 已封装现有后端接口，页面迁移时直接调用这些客户端即可。
